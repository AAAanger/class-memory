# 识别课表截图

上传教务系统截的课程表 → 自动拆成「星期 + 节次 + 周次 + 教室」→ 你核对 → 导入。

---

## 一、它是怎么工作的

```
① 你在网页上选图
② 浏览器里压缩到 1800px，转成 base64
③ POST /api/parse-timetable  （唯一需要服务端的一步）
④ 服务端带着 Key 调多模态模型，要求它只输出一个固定格式的 JSON
⑤ 前端拿到 JSON → 解析层校验、翻译、去重
⑥ 给你一张可勾选的清单
⑦ 你点「导入」，才真正写进课表
```

三个关键设计，都是被坑出来的：

**1. 识别结果绝不直接写库。**
视觉模型在这种密集中文表格上一定会出错（漏读一格、把周次读串）。所以中间必须有一层人工核对，勾掉错的那几条就行。**「悄悄导错」比「不能导入」糟糕得多。**

**2. 只信「第几节」，不信时间。**
模型只负责读出 `[3,4]`，几点到几点由你本地的「作息时间表」翻译。这样即使模型读错了星期，时间也不会跟着错；而且换学校只需要改作息表，不用改提示词。

**3. 同一门课的多条不合并。**
你课表里「数据结构与算法分析」第 1-2 周在周一第 3-4 节，第 5-12、14 周挪到周五第 5-6 节 —— 这是两条独立的时段，必须分开存。数据库里本来就是一个课程对应多个时段，`matchSlot()` 按时间各自匹配，所以期末复习时按周翻也是对的。

## 二、配一个模型 Key（约 3 分钟）

### 1. 选一家

都是 OpenAI 兼容格式，代码通用：

| 服务 | 控制台 | 备注 |
|---|---|---|
| 阿里云百炼（通义千问 VL） | https://dashscope.console.aliyun.com | 有新用户免费额度，中文表格认得不错，建议先试这家 |
| 智谱（GLM-4V 系列） | https://open.bigmodel.cn | 便宜 |
| 火山方舟（豆包视觉） | https://console.volcengine.com/ark | 便宜 |
| OpenAI（GPT-4o / 4.1） | https://platform.openai.com | 效果最好，需要外币卡 |

注册 → 开通 → 创建 API Key，复制那串 `sk-...`。

> 具体模型名和接口地址以各家官网当前文档为准，下面的值只是示例。

### 2. 填进项目

复制 `.env.example` 为 `.env.local`，填三行：

```bash
AI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
AI_API_KEY=sk-你的Key
AI_MODEL=qwen-vl-max
```

**保存后必须重启** `npm run dev`（环境变量只在启动时读一次）。

### 3. 验证

打开课表页 → 「识别课表截图」→ 选一张 → 「开始识别」。

如果报 `服务端还没有配置模型 Key`，说明 `.env.local` 没读到，检查：

- 文件名是不是 `.env.local`（不是 `.env.local.txt`，Windows 隐藏扩展名容易踩）
- 是不是放在 `class-memory` 根目录，和 `package.json` 同一层
- 有没有重启 dev server

## 三、不用 Key 也能用

「识别课表截图」面板里有个 **「载入示例课表」** 按钮：

它不联网、不花钱，直接把 `src/data/sample-timetable.js` 里那份虚构的示例课表（12 门课 / 27 个时段）灌进同一套解析流程。

作用有两个：

- 你先看看整个流程和界面长什么样
- 万一不想折腾 Key，课表也能一步到位（那份文件就是你的真实课表）

不需要了就把 `src/data/sample-timetable.js` 删掉，再把 `Timetable.jsx` 里那个按钮去掉。

## 四、识别不准怎么办

按顺序试：

1. **分几张截图**。一张图里塞 6 个节次 × 7 天，模型容易漏。按「上午一张、下午一张」分开截，准确率明显上升。
2. **别压缩太狠**。`src/lib/image.js` 里 `compressToDataUrl` 默认 1800px / 0.85，可以调到 2200 / 0.9。
3. **换更强的模型**。`AI_MODEL` 换成同系列里更大的那个。
4. **改提示词**。在 `server/vision.js` 的 `TIMETABLE_PROMPT` 里，把你学校表格的特殊之处写清楚（比如「周五下午这一栏是合并单元格」）。
5. **最后靠人工**。预览里勾掉错的，导入后在课表页点「改」。

统计上：4 张以内的清晰截图，主流视觉模型一般能读对 90% 以上；剩下的靠预览那一步挡住。

## 五、成本

一次识别 = 1~4 张图 + 一段约 700 字的提示词，大约 5k~15k 输入 token，输出不到 1k。

按国内视觉模型的价位，**一次几分钱**。一个学期改十几次课表，也就几毛。

嫌贵就只在开学时跑一次，之后手动改。

---

## 六、隐私

这一步会把课表图片发到模型服务商，图片会离开你的手机。

课表本身不含个人信息（除非截图带了姓名学号 —— 你这张左上角就有「学号 / 姓名」，**建议截掉再传**）。

已经在用的板书照片不受影响，它们始终只存在你手机里。

---

## 七、部署到线上时

Vercel 项目 → `Settings` → `Environment Variables`，把同样三个变量加进去：

| Name | Value |
|---|---|
| `AI_BASE_URL` | 你的兼容地址 |
| `AI_API_KEY` | 你的 Key |
| `AI_MODEL` | 模型名 |

改完 `Redeploy` 一次。接口文件是 `api/parse-timetable.js`，Vercel 会自动把它变成 `POST /api/parse-timetable`。

注意：Vercel 请求体上限 4.5MB，所以前端上传前会压缩，一次最多 4 张。

## 八、相关文件

| 文件 | 干什么 |
|---|---|
| `server/vision.js` | 提示词 + 调模型 + 抠 JSON |
| `server/handler.js` | 校验参数、检查 Key、统一返回 |
| `api/parse-timetable.js` | Vercel 函数入口 |
| `vite.config.js` | 开发时的中间件（`npm run dev` 也能用这个接口） |
| `src/lib/timetableImport.js` | **解析层**：白名单校验、翻译、去重 |
| `src/lib/periods.js` | 节次 ↔ 时间的换算 |
| `src/views/ImportTimetable.jsx` | 上传 + 核对 + 导入界面 |
| `src/data/sample-timetable.js` | 示例课表 |
| `scripts/test-timetable-import.mjs` | 解析层的 39 条测试 |

改了解析层或提示词，跑一遍：

```bash
npm test
```
